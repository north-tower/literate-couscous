# Phase 1.3 — Job payload for local runs

> **Status:** Implemented in `jobs.py`, `app.py`.  
> **Related:** [sendline-desktop-transition-plan.md](./sendline-desktop-transition-plan.md) Phase 1.3

---

## Shared payload builder

| Function | Purpose |
|----------|---------|
| `jobs.build_job_payload(user_id, job_id)` | Campaign + decrypted LinkedIn creds + `egress.assign_proxy()` → `run`, `secrets`, `attachment`, `proxy_label`. Raises `JobPayloadError`. |
| `jobs._write_job_payload` | Server mode only: writes `run.json` / `secrets.json` under `db.job_dir` (unchanged behavior for `execution_mode=server`). |
| `jobs.build_agent_work_bundle(user_id, job_id, request_base_url=...)` | JSON bundle for `GET /api/agent/work` (initial claim). |

**Local users (`execution_mode=local`):**

- No `run.json` / `secrets.json` on the server when a job would be prepared for the VPS worker.
- `jobs.start_next()` does not mark the job `running` or spawn `worker.py` (waits for desktop agent in Phase 1.4).

## Agent work bundle shape

`build_agent_work_bundle` returns (passwords only inside `secrets`; never log this object):

```json
{
  "job_id": 12,
  "user_id": 3,
  "people_count": 2,
  "people_names": ["…"],
  "message_template": "Hi {name}, …",
  "attachment": {
    "name": "deck.pdf",
    "path": "/api/agent/jobs/12/attachment",
    "download_url": "https://host/api/agent/jobs/12/attachment?expires=…&sig=…"
  },
  "run": {
    "people_names": ["…"],
    "message_template": "…",
    "attachment_path": null,
    "ledger_path": null
  },
  "secrets": {
    "linkedin_username": "…",
    "linkedin_password": "…",
    "proxy_url": "http://…"
  },
  "proxy_label": "exit-7",
  "ledger": {
    "use_local_path": true,
    "filename": "send_ledger.json",
    "server_sync": false
  }
}
```

The desktop agent (Phase 2) should:

1. Write `run.json` with `attachment_path` set to a **local** file after download.
2. Set `ledger_path` to `%LOCALAPPDATA%\Sendline\…\send_ledger.json` (or `userData` equivalent).
3. Write `secrets.json`, run worker, delete secrets after worker reads them (same as VPS today).

## Send ledger (1.3.7)

Server-side `data/users/<id>/send_ledger.json` is **not** copied to the desktop. Dedupe history on the operator PC lives only in the local ledger file. **Future work:** optional sync or merge policy if the same user runs from multiple machines.

---

## Attachment download (1.3.4)

| Method | Path | Auth |
|--------|------|------|
| `GET` | `/api/agent/jobs/<job_id>/attachment` | `Authorization: Bearer <agent token>` **or** query `expires` + `sig` (HMAC, 1 hour TTL) |

Signed URLs are generated by `jobs.attachment_download_url()` inside the work bundle. Job must belong to the token’s user; file must live under `attachments_dir(user_id)`.

## Manual smoke test (Python shell)

After a user has campaign + LinkedIn saved and a queued job id:

```python
import jobs, db
uid = 1
jid = 1
bundle = jobs.build_agent_work_bundle(uid, jid, request_base_url="http://127.0.0.1:5055")
assert bundle["people_names"]
assert "linkedin_password" in bundle["secrets"]
# Do not print bundle — contains secrets
```

Download (replace token and job id):

```bash
curl -H "Authorization: Bearer YOUR_TOKEN" \
  -o deck.pdf "http://127.0.0.1:5055/api/agent/jobs/1/attachment"
```
